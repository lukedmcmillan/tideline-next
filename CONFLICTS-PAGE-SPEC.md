## WHAT IT IS

A system that:
1. Detects when sources in the Tideline feed cover the same story with contradictory conclusions
2. Scores the magnitude of the divergence (0–10)
3. Surfaces high-scoring conflicts to subscribers as a professional signal
4. Explains why the conflict matters in compliance or investment terms

**Tideline does not adjudicate who is correct.** It shows the gap and quantifies it. This is what expert users (lawyers, ESG analysts, compliance teams) will respect. Two authoritative sources disagreeing is the signal. Tideline shows you the signal.

## DATABASE SCHEMA

```sql
CREATE TABLE IF NOT EXISTS divergences (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  story_id_a uuid REFERENCES stories(id),
  story_id_b uuid REFERENCES stories(id),
  tracker_tag text NOT NULL,
  divergence_score numeric(3,1) NOT NULL CHECK (divergence_score BETWEEN 0 AND 10),
  source_a_name text NOT NULL,
  source_a_type text,           -- 'GOVERNMENT' | 'NGO' | 'ACADEMIC' | 'PRESS'
  source_a_claim text NOT NULL, -- one sentence
  source_a_date timestamptz,
  source_a_url text,
  source_b_name text NOT NULL,
  source_b_type text,
  source_b_claim text NOT NULL,
  source_b_date timestamptz,
  source_b_url text,
  headline text,                -- generated by Haiku, falls back to tracker_tag
  why_it_matters text NOT NULL, -- one sentence compliance/investment implication
  detected_at timestamptz DEFAULT now(),
  dismissed_at timestamptz,     -- null = active
  is_active boolean DEFAULT true
);

CREATE INDEX idx_divergences_tracker ON divergences(tracker_tag);
CREATE INDEX idx_divergences_active ON divergences(dismissed_at) WHERE dismissed_at IS NULL;
```

**Severity derived from score at render (not stored):**
- Score ≥ 8.0 → HIGH (red `#E24B4A`)
- Score 5.0–7.9 → MEDIUM (amber `#EF9F27`)
- Score < 5.0 → not surfaced

## DETECTION LOGIC — HOW IT WORKS

### Step 1 — Story clustering (nightly, 04:00 UTC)

For each pair of stories:
- Published within a 72-hour window
- Tagged to the same `tracker_tag`
- From different source organisations

```sql
-- Find candidate pairs
SELECT a.id as story_a, b.id as story_b, a.tracker_tag
FROM stories a
JOIN stories b ON (
  a.tracker_tag = b.tracker_tag
  AND a.id < b.id
  AND ABS(EXTRACT(EPOCH FROM (a.published_at - b.published_at))) < 259200  -- 72 hours
)
WHERE a.published_at > now() - interval '7 days'
  AND a.source_name != b.source_name
```

### Step 2 — Divergence scoring via Haiku

Send both story summaries to Claude Haiku:

```
Given these two stories covering the same ocean governance event:

STORY A: [title] | Source: [source_name] | [short_summary]
STORY B: [title] | Source: [source_name] | [short_summary]

Score their divergence on these dimensions (0-10 each):
1. Factual claim divergence (different facts stated as true)
2. Conclusion divergence (different implications drawn)
3. Framing divergence (same facts, materially different emphasis)
4. Source authority divergence (one primary source, one secondary)

Return JSON only:
{
  "factual": [0-10],
  "conclusion": [0-10],
  "framing": [0-10],
  "authority": [0-10],
  "composite": [0-10],
  "source_a_claim": "[one sentence summary of A's position]",
  "source_b_claim": "[one sentence summary of B's position]",
  "headline": "[short punchy headline for the conflict, max 12 words]",
  "why_it_matters": "[one sentence compliance or investment implication]"
}
```

**Composite formula:**
```
composite = (factual × 0.40) + (conclusion × 0.30) + (framing × 0.20) + (authority × 0.10)
```

### Step 3 — Quality gate before insert

Only insert if:
- `composite >= 5.0`
- Both sources are distinct organisations
- `why_it_matters` is not empty
- No existing active divergence for the same `story_id_a` + `story_id_b` pair

### Step 4 — Auto-resolution

Mark `dismissed_at = now()` automatically when either source story is older than 14 days. Do not delete — retain for historical view.

## UI COMPONENT SPEC — DivergenceCard

Follow the dark Google-style pattern from the Trackers page. These are the component rules:

### Card structure (top to bottom):

**1. Meta row**
- Severity pill: filled colour (HIGH red / MEDIUM amber), label text
- Domain pill: outline only (no solid fill — design rule), tracker_tag in title case
- Timestamp: right-aligned, time-ago format, DM Mono, muted colour `#8BA0BC`

**2. Divergence bar row**
- Label: "DIVERGENCE" in DM Mono caps, muted
- Progress bar: 0–10 scale, coloured by severity
- Score: right-aligned "7.8 / 10" in severity colour, DM Mono

**3. Headline**
- Large bold text, full width
- Falls back to tracker_tag in title case if no headline stored
- DM Sans, no em dashes

**4. Two-column source grid**
- Vertical divider between columns, centred "vs" pip
- Each column: source avatar (square, initial letter), bold source name, mono-caps source type label (GOVERNMENT / NGO / ACADEMIC / PRESS), claim text (full wrap, no truncation), mono date below
- **Critical:** `min-width: 0` on both columns. No `overflow: hidden`. Text wraps fully.

**5. Insight row**
- Left border: amber `#EF9F27`
- "Why this matters:" bold label + body text
- Star icon left

**6. Footer actions**
- "Add to workspace" — teal filled button
- "View sources" — ghost button
- "Track dispute" — ghost button
- "Dismiss" — plain text far right, wires to `PATCH /api/divergences/[id]/dismiss`

### Design constraints (all standard Tideline rules):
- No em dashes anywhere
- No blue colour
- No solid domain badges — outline only
- No beige backgrounds
- DM Sans for all body text
- DM Mono for scores, timestamps, source type labels
- Background: `#0B1628` / `#0D1E35`
- Text primary: `#E8EDF4`, muted: `#8BA0BC`

## MORNING BRIEF INTEGRATION

When a divergence has `divergence_score >= 6.0`, include in the morning brief generator:

Brief line format:
> "[DOMAIN]: Authoritative sources are reporting [opposite conclusions / conflicting data] on [event]. Divergence score [X.X]. Details in platform."

The morning brief function should query:
```sql
SELECT * FROM divergences
WHERE dismissed_at IS NULL
  AND divergence_score >= 6.0
  AND detected_at > now() - interval '24 hours'
ORDER BY divergence_score DESC
LIMIT 3
```
